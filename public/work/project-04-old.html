(03) (Background)

  1. (01)

    Trust

    수집용 비디오게임 거래 시장에는 온라인에서 구매자와 판매자 양쪽을 보호할 장치가 부족했습니다.

  2. (02)

    Fragmented

    컬렉션 관리와 빠른 거래를 한 곳에서 해결할 수 있는 종합적인 솔루션이 없었습니다.

  3. (03)

    Pricing

    게임 아이템이 과대평가되는 경우가 많았고, 판매자는 적정 가격을 정하기 어려웠습니다.

(04) (Solution)

  • (01)

    Protection for Both

    구매자와 판매자 모두를 보호

  • (02)

    Reasonable Price

    모두에게 합리적인 가격

  • (03)

    Sell Things Fast

    빠른 판매 과정

  • (04)

    Buy, Sell, Collect

    구매 · 판매 · 수집을 하나의 플랫폼에서

(But)

디자인 과정 없이, 서비스가 먼저 출시되었습니다.

해외 비디오게임 시장의 투자유치 시즌에 맞춰, 많은 상품 등록으로 데이터베이스를 확보하는 일이 우선이었기 때문입니다. 그래서 제 역할은 빈 화면에서 시작하는 것이 아니라, 이미 움직이고 있는 서비스를 멈추지 않고 고쳐 나가는 일이었습니다.

(05) (UX Process)

  1. (01)

    Audit

    기존 화면 설계의 구조적 미흡점을 점검하고, 초기 러프 설계에서 빠진 기능과 예외 상황, 화면 간 연결 관계를 정리했습니다.

  2. (02)

    Architecture

    Figma로 로그인 · 회원가입, User, Game, More 영역을 아우르는 서비스 전체의 Information Architecture와 User Flow를 재구성했습니다.

  3. (03)

    Prototype

    사용자와 관리자 관점의 주요 시나리오로 프로토타입을 만들고, 실제 플로우를 시뮬레이션하며 탐색의 불편, 정보 전달의 불명확성, 화면 간 연결성 문제를 찾아냈습니다.

  4. (04)

    Refine

    찾아낸 문제를 UI 설계에 반영해 정보 구조와 인터랙션을 개선하고, 화면 간 일관성을 확보하며 서비스를 단계적으로 고도화했습니다.

(06) (Design System)

화면 하나를 고치는 대신, 결정의 기준을 만들었습니다.

초기 개발 과정에서 화면별 디자인 기준이 정립되지 않아 UI의 일관성이 떨어졌고, 디자인과 개발 사이의 해석 차이로 반복적인 수정과 커뮤니케이션이 이어졌습니다.

이 문제를 개별 화면의 개선이 아닌 시스템 관점의 UX 문제로 정의하고, 디자인 스타일가이드와 주요 화면 가이드를 구축해 UI 요소의 구조와 사용 원칙을 체계화했습니다.

그 결과 디자인 의사결정의 기준이 하나로 정리되어 디자이너와 개발자의 협업이 효율적으로 바뀌었고, 이후의 리뉴얼을 더 빠르고 안정적으로 확장할 수 있는 기반이 마련되었습니다.

(07) (GUI)

Product Details

기존 UI는 버튼과 탭 같은 인터랙션 요소의 위계가 불분명해 정보의 중요도와 기능을 한눈에 파악하기 어려웠고, 상품 이미지에도 일관된 노출 기준이 없어 콘텐츠의 신뢰도를 떨어뜨렸습니다.

정보 구조와 사용자 인지 관점에서 UI 요소의 위계를 다시 세우고, 주요 컴포넌트와 상품 콘텐츠에 일관된 기준을 적용했습니다. 브랜드를 대표하는 퍼플 컬러는 핵심 인터랙션과 주요 강조 영역에만 사용해 시선을 이끄는 동시에 브랜드 인지도를 높였습니다.

User-friendly Details

직관적인 메뉴 아이콘을 새로 디자인하고, 불필요한 기능과 정보는 덜어냈습니다. 읽기 좋은 텍스트 컬러와 충분한 터치 영역으로 접근성을 높였습니다.

비슷한 기능의 화면에는 같은 디자인 원칙을 적용하고, 다양한 디바이스의 화면 크기와 환경에서도 무리 없이 작동하도록 유연한 레이아웃을 고려했습니다.
